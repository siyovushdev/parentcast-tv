# M3 — HOME, PIN-вход и подготовка privileged kiosk

Дата: 2026-11-02. База M2: `940564113dc1c68184211cdfc1e73d43c6dc7d99`.
Ветка `m3/home-kiosk`, Draft PR в `m2/playlist-import`. Merge/Release не выполнялись.

**Результат:** HOME и локальный PIN-выход реально проверены на H728. Полноценная kiosk-защита
**не принята**: обычный APK не блокирует системные SETTINGS/ASSIST. Отдельный privileged ALWAYS
кандидат реализован и собран, но не устанавливался. Три reboot NOT_RUN по указанию владельца.

## Реализация

- Отключённый по умолчанию HOME alias, штатный HOME role picker, сохранение доступного исходного
  Launcher до включения. Возврат по PIN отключает alias и открывает системный chooser/«Всегда».
- MENU/DPAD Center hold и Ctrl+Alt+P открывают только PIN-форму. Все чувствительные локальные
  действия проверяют родительскую сессию; BACK возвращает просмотр. PIN M1 не менялся.
- 5 попыток/10 минут с сохранением до PBKDF; проверка в фоне. Сессия 2 минуты idle, закрывается
  при background/возврате в плеер. Маскирование PIN, запрет сохранения view-state/autofill и FLAG_SECURE.
- Child on/off, отдельные фактические HOME/NONE/PINNED/LOCKED. DPC API поддержан без назначения DO;
  без разрешения startLockTask не вызывается и screen pinning не предлагается как kiosk.
- Автопродолжение выключено по умолчанию: сохранённый PLAY становится PAUSE той же позиции.
  PAUSE/STOP не переходят в PLAY; при ошибке записи безопасного intent autoplay запрещён.
  Явный PLAY пульта остаётся отдельным действием.
- HOME/launcher/private kiosk Activity передают единственного владельца Media3/HTTP до создания нового.
  Старые HTTP callbacks не могут менять очередь после передачи. Живой handoff учитывает intent и
  storageWarning предыдущего Coordinator, а не только существование Activity.
- Нет boot receiver, фонового старта Activity, Activity restart loop, hidden API или изменений yt-dlp/Media3.
- Отдельный вариант `privileged` с private ALWAYS-root и одноразовым PIN admission, фактической
  проверкой LOCKED, ограниченным ожиданием NONE и finish-root выходом. Нет постоянного privileged
  autoarm на boot. Подробности и условия системной установки: [план](../M3-privileged-plan.md).

Независимое ревью субагентами выявило и исправило отказ запуска trial без видимой ошибки,
лишний persistent child flag для одноразового trial и обход safe-start при передаче живого Activity
после ошибки диска. Это локальные исправления в M3, без расширения архитектуры.

## Ограничения и классификация

- **IN SCOPE:** системные SETTINGS/ASSIST обходят HOME + PIN. Полный kiosk пока FAIL/NOT_RUN;
  нужен принятый privileged ALWAYS либо официальный DPC deployment. Ни HOME, ни immersive не равны LOCKED.
- **IN SCOPE:** ADB after reboot не подтверждён: service port5555, persist port пуст, USB фактически
  не проверен. Reboot запрещён владельцем; автоматический HOME boot поэтому не принят аппаратно.
- **UNKNOWN:** целостность OEM framework-res: apksigner v3 digest mismatch на исходном устройстве;
  предоставленный cert совпал с TvSettings, отличается от android. [Read-only исследование](../M3-privileged-plan.md).
- **OUT OF SCOPE:** root/ADB владельца, factory reset, управление самим телевизором и физическое
  вмешательство не являются границами абсолютной защиты. M4/облако/аккаунты/другие проекты не менялись.
- **REGRESSION:** повторный HTTP bind при отдельной HOME Activity найден и исправлен в M3;
  после передачи владельца один плеер/server, панель отвечает. Данных M0–M2 не удаляли.

Следующий шаг: подготовить подтверждённый recovery/ADB после boot и исходный доверенный образ,
затем отдельно согласовать конкретную priv-app установку и откат по плану. До этого H728 безопасно
остаётся в обычном Launcher, а M3 Draft PR не объявляется аппаратно принятой kiosk-блокировкой.
