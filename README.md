# ParentCast TV

Рабочее название нового домашнего проекта. Не является развитием или копией FamilyTV.

**Назначение:** родители выбирают YouTube-видео с Android-телефона или Ubuntu,
а Android-приставка воспроизводит только составленную ими программу.

## Статус

Ветка `m3/home-kiosk` добавляет HOME, локальную PIN-защиту и настройку автопродолжения
поверх M2 (`m2/playlist-import`). M2 развивает M1 (`m1/lan-parent-control`) и добавляет импорт публичных
статических YouTube-плейлистов и фиксированные сохранённые подборки. M1 добавляет к Android-плееру M0 встроенный родительский
LAN-веб-пульт. Плеер использует Kotlin, Media3 и yt-dlp `2026.10.26` на встроенных
Python 3.12/QuickJS. Есть атомарная очередь, сопряжение браузеров по PIN и одноразовому коду,
отдельные отзываемые токены и русская адаптивная панель. NewPipe сохранён для сравнения.
Приватный репозиторий: `siyovushdev/parentcast-tv`. Это не защищённый детский режим;
фактические результаты находятся в `docs/reports/M0-ytdlp-media3.md` и `docs/reports/M1.md`.

## Состав решения

- Один Android APK на приставке: нативный плеер, очередь, локальное хранение,
  HTTP-сервер и встроенная родительская веб-панель.
- Телефон и Ubuntu используют одну адаптивную веб-панель по домашней сети.
- Приставка получает видеопоток сама. Постоянно работающий Ubuntu для локального просмотра не нужен.
- Удалённое управление через защищённый канал — отдельный этап, не M1.

## Сборка M0–M3

Нужны JDK 17 и Android SDK с platform 35. Все версии Gradle и библиотек закреплены в проекте.
Из корня репозитория:

```bash
export JAVA_HOME=/path/to/jdk-17
export ANDROID_HOME=/path/to/Android/Sdk
./gradlew testDebugUnitTest assembleDebug lintDebug --no-daemon
```

Debug APK создаётся как `app/build/outputs/apk/debug/app-debug.apk`; его applicationId —
`dev.siyovush.parentcast.tv.debug`. Минимальный SDK — 33, целевой стенд M0 — H728 с Android 14.

## Запуск на однозначно опознанной H728

Не используйте эти команды для случайного телефона или неопознанного ADB-устройства.
Установка не меняет Launcher, HOME, Device Owner или системные настройки:

```bash
adb -s <SERIAL_H728> install -r app/build/outputs/apk/debug/app-debug.apk
adb -s <SERIAL_H728> shell am start -n dev.siyovush.parentcast.tv.debug/dev.siyovush.parentcast.tv.ui.MainActivity
```

Очередь изначально пуста. На экране просмотра удержание MENU/DPAD Center (или Ctrl+Alt+P на клавиатуре) открывает
только форму PIN. После правильного PIN доступен экран родителя. Добавьте обычную, короткую или Shorts YouTube-ссылку, затем нажмите
«Играть». Back из debug-экрана возвращает плеер. Во время видео собственные кнопки и YouTube UI
не отображаются.

## Веб-пульт M1

1. При первом запуске задайте PIN из 6–12 цифр на родительском debug-экране.
2. Для смены PIN введите действующий и новый PIN. Очистка данных приложения не требуется.
3. Для нового сопряжения введите действующий PIN и нажмите «Сопряжение на 2 минуты».
   На телефоне или Ubuntu откройте IPv4-адрес панели, показанный на ТВ (на стенде
   `http://192.168.68.121:8765`), и введите PIN и одноразовый код.
4. Сопрягайте каждый браузер отдельно. Токены можно отозвать на ТВ или в панели; они не
   помещаются в URL. После отзыва очередь и управление снова требуют сопряжения.
5. Добавление ссылок не запускает просмотр. Для немедленного запуска есть отдельная команда
   «Включить сейчас». Статусы и ошибки приходят от Media3, а не означают успех по HTTP 200.
6. Закрытие браузера не останавливает приставку. После перезапуска приложения сохраняются
   очередь, позиция и намерение PLAY/PAUSE/STOP.

M1 использует HTTP только внутри доверенной домашней сети. Трафик не шифруется; HTTPS,
управление через интернет и публичная панель не реализованы. Тестовая YouTube-сессия M1 не
выдаётся за production-авторизацию.

## Плейлисты и сохранённые подборки M2

В панели вставьте ссылку в отдельный раздел импорта плейлиста и получите предпросмотр.
Отметьте ролики и нажмите «Добавить выбранные». Ни получение списка, ни сохранение подборки
не запускают плеер. Для завершённых VOD с неизвестной доступностью это явно написано:
список YouTube не доказывает будущего воспроизведения. Ошибки страниц помечены PARTIAL;
выбрать можно только явно полученные допустимые элементы. Неподтверждённая публичность
блокирует применение, плейлисты более 500 элементов отклоняются с объяснением.

«Сохранить выбранные как подборку» создаёт приватный фиксированный список videoId на приставке.
Подборку можно посмотреть, добавить повторно или удалить. Изменение исходного YouTube-плейлиста
её не обновляет. Добавление использует queueVersion и один атомарный batch с receipt;
повтор команды после потери ответа не дублирует элементы (окно идемпотентности 24 часа).
Предпросмотр отменяется и истекает через 15 минут; это временные данные, а не подписка.

Поддержаны публичные статические PL/OLAK5uy плейлисты. Mix, uploads/feed, private/unlisted,
эфиры и премьеры не поддерживаются. Получение списка анонимное и не меняет тестовые cookies,
которые существующий плеер продолжает использовать. Результаты: `docs/reports/M2.md`.

## HOME и локальный родительский вход M3

Удерживайте MENU или DPAD Center (3 секунды, также поддержан стандартный long-press),
чтобы открыть форму родительского PIN M1. Неверные попытки ограничены: 5 за 10 минут,
счётчик сохраняется после перезапуска. Настройки закрываются при уходе из приложения,
возврате к просмотру и через 2 минуты бездействия. PIN не добавляется в URL или логи.

Сначала проверьте доступность сохранённого Launcher в настройках. Нажмите «Выбрать ParentCast
как HOME» и завершите штатный Android-выбор. Затем включите детский просмотр. Автозапуск
обеспечивает сама система для выбранного HOME, без фонового boot receiver. Автопродолжение PLAY
по умолчанию выключено: при новом запуске сохранённый PLAY становится PAUSE с той же позицией;
PAUSE/STOP не запускаются самопроизвольно. Явная команда PLAY веб-пульта работает отдельно.

Для выхода откройте PIN-форму, войдите и нажмите «Вернуть штатный Launcher и отключить HOME».
Просмотр остановится, детский режим выключится, собственный HOME alias отключится.
Android предложит выбрать штатный HOME: отметьте сохранённый Launcher и нажмите «Всегда»; факт проверяется resolver,
а не только появлением Launcher на экране. Запасной путь владельца по уже проверенному ADB:
`python3 tools/m3_restore_home.py --serial <H728_SERIAL> --home <SAVED_HOME_COMPONENT>`.

**HOME + PIN не блокируют системные выходы.** В обычном APK настоящий Lock Task запускается только
при официальном разрешении DPC, screen pinning не используется как замена. На стенде Device Owner
отсутствует; его назначение не выполняется. Фактические ограничения и NOT_RUN reboot при
неподтверждённом возврате ADB перечислены в `docs/reports/M3.md`. M4 не реализуется.

По отдельному дополнению M3 подготовлен вариант `assemblePrivileged`: тот же debug package и signer,
но отдельная private Activity `lockTaskMode="always"`. В Android 14 этот путь требует установки,
распознанной как privileged, и фактического `LOCK_TASK_MODE_LOCKED`. Кандидат на H728 не устанавливался,
первый пробный сеанс не включается автоматически после boot. Для исследования не нужен приватный
platform-ключ. Проверенные свойства прошивки, ограничения данных и условный план установки/отката:
[`docs/M3-privileged-plan.md`](docs/M3-privileged-plan.md). Обычный `assembleDebug` не содержит ALWAYS Activity.

## Главные границы

Только родительский выбор. Никаких рекомендаций, встроенной страницы YouTube,
переходов во внешнее приложение или Google Login через WebView. Тестовые cookies допускаются
только в debug при ручном включении владельцем; агент не читает их содержимое. Это не production-
авторизация. Рекламу и другое содержимое внутри роликов родители проверяют самостоятельно.
Неофициальный способ получения потоков принят владельцем с риском периодических поломок.

M0–M1 — прототип плеера и родительского пульта, **не защищённое детское устройство**.
До приёмки режима HOME/Lock Task нельзя оставлять ребёнку приставку как готовое ограниченное устройство.
