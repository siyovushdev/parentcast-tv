# ParentCast TV — техническое задание v0.1

Дата подготовки: 31 октября 2026 года.
Статус: стартовая спецификация на основе обсуждения с владельцем.
Цели и жёсткие ограничения подтверждены владельцем. Детали поведения ниже, обозначенные
как проектные решения, выбраны для начала работы и могут меняться без подмены основной цели.

## 1. Цель и подтверждённые требования

Создать домашний управляемый видеоканал для детей. Родители выбирают YouTube-контент
на Android-телефоне или Ubuntu. Приставка, подключённая к ТВ по HDMI, показывает его
последовательно. Дети не выбирают видео и не выходят из режима просмотра обычным пультом.

Подтверждено владельцем:

- Источник контента — только YouTube.
- Полноэкранный просмотр без детских кнопок, рекомендаций, комментариев и постороннего интерфейса YouTube.
- Управление родителями с Android и Ubuntu по домашней сети, впоследствии из другой сети.
- Несколько роликов в очереди и добавление плейлистов.
- Приложение на приставке должно работать как HOME; нужен защищённый родительский режим.
- Встроенную в само видео рекламу и полезность содержимого родители проверяют самостоятельно.
- Неофициальное получение YouTube-потоков допустимо; риск поломок при изменениях YouTube принят.
- Владелец сообщил о платном YouTube без рекламы. Это не основание считать наш неавторизованный клиент Premium-клиентом.
- Реализация выполняется через Kimi Code, по этапам с проверкой результатов.

## 2. Рабочие технические решения

Название: **ParentCast TV**. Новый приватный репозиторий `siyovushdev/parentcast-tv`.
Не изменять существующий FamilyTV.

Целевой стенд по имеющемуся контексту — H728, Android 14, экран 1920×1080.
Модель, версию ОС и доступные декодеры подтвердить на устройстве; это не результаты текущей проверки.
Приложение не должно требовать root для обычного воспроизведения.

Состав: один APK и встроенная адаптивная веб-панель для обоих родительских устройств.
Отдельные Android- и Ubuntu-клиенты не являются обязательными для первой версии.
Нативное «Поделиться → отправить на ТВ» на телефоне — возможное последующее улучшение, не M0–M4.

Android: Kotlin, Media3/ExoPlayer, собственный нативный экран без WebView/iframe.
Первый кандидат получения потоков и метаданных — NewPipe Extractor за интерфейсом `YouTubeSource`.
Его использование независимо от приложения NewPipe предусмотрено проектом [S1].
Нельзя считать библиотеку проверенной на H728 до M0.

Версии Gradle/AGP/Kotlin/Media3/extractor фиксировать точными значениями после проверки совместимости.
Нельзя использовать `+`, плавающую ветку `dev`, `latest` или недолговечный SNAPSHOT в принятой сборке.
Выбор minSdk привязать к целевому стенду и библиотекам; поддержка старых приставок не входит в M0.
Если выбран minSdk ниже 33, проверить требования extractor к desugaring по актуальному README [S1].

## 3. Где выполняется работа

Телефон / Ubuntu → команды и ссылки → приставка → получение и воспроизведение потока.

Приставка — единственный источник истины для очереди и состояния плеера.
На ней хранятся видео-ID, порядок, позиция, родительские настройки и права доступа.
Телефон и ПК не ретранслируют изображение и не обязаны оставаться включёнными.
Постоянный сервер Node/Python, транскодирование на Ubuntu и облачный backend не нужны.
Интернет требуется самой приставке для YouTube; Wi-Fi обеспечивает связь с родительским пультом.

В M0 достаточно одного Android-модуля и разделения на пакеты: UI, playback, queue, youtube, storage.
Сетевой API и веб-панель добавляются в M1, не раньше проверки воспроизведения.

## 4. Детский экран

Во время просмотра — видео с сохранением пропорций, без нашего списка роликов,
названий каналов, обложек, рекламы приложения, ссылок и интерактивных оверлеев YouTube.
Пустая очередь, пауза/остановка и длительная ошибка — спокойный экран нашего приложения.
Подробности ошибок и диагностика доступны только родителю.

Не загружать страницу YouTube и не использовать внешний плеер как автоматический fallback.
Никакого режима поиска, рекомендаций, подписок на каналы, «похожего ролика» или бесконечной ленты.
Субтитры в первой версии выключены; управление ими не добавлять в M0.
Брендинг, рекомендации или реклама, нарисованные автором внутри кадров видео, относятся
к содержимому ролика, которое проверяет родитель, а не к интерфейсу приложения.

В M0 допускается отдельный отладочный экран ввода ссылок и команд. Он явно помечен как
прототип, не является защищённым родительским режимом и не показывается поверх видео.
Системные оверлеи громкости/выключения и меню самого телевизора не считать контролируемыми приложением.

## 5. Родительский пульт (M1 и далее)

Одна адаптивная панель на русском языке. Статические файлы поставляются внутри APK,
панель и API обслуживаются приставкой. Выбрать минимальную совместимую HTTP-библиотеку,
не писать собственный HTTP-парсер и не вводить большой frontend framework без необходимости.

Основные действия: добавить ссылку; добавить несколько ссылок; воспроизвести;
пауза/продолжение; следующий; остановить; изменить порядок; удалить элемент;
очистить ожидающую очередь; посмотреть состояние и ошибки.
«Включить сейчас» — отдельная явно подписанная команда, не побочный эффект добавления.
В M2 добавляются импорт плейлиста с предпросмотром и сохранённые подборки.

Панель различает: команда получена, ролик загружается, реально воспроизводится, пауза,
ошибка, приставка недоступна. Нельзя показывать «воспроизводится» по HTTP 200.
Статус должен отражать события настоящего плеера и содержать время последнего обновления.

## 6. Очередь и правила воспроизведения

Каждый элемент имеет собственный `queueItemId` и `videoId`; одинаковый ролик может быть
добавлен повторно намеренно. Порядок определяется родителем, а не ответом рекомендаций.

Проектные значения по умолчанию:

| Событие | Поведение |
|---|---|
| Добавить ролик | В конец ожидающей очереди; текущий не прерывается |
| Включить сейчас | Прервать текущий, не возвращать его автоматически; проиграть новый, затем оставшуюся очередь |
| Следующий | Текущий пометить пропущенным, перейти к следующему |
| Пауза | Оставить позицию, не переключать видео |
| Остановить | Прекратить просмотр, сохранить позицию и очередь; продолжение только явной командой |
| Очистить очередь | Удалить ожидающие элементы; текущий не прерывать |
| Удалить текущий | Требовать явной команды «удалить и перейти к следующему» |
| Конец последнего ролика | Экран ожидания, без автоподбора |
| Повтор | По умолчанию выключен; родитель может включить повтор выбранной очереди позже |
| Перезапуск процесса/питания | Восстановить очередь и последнее сохранённое состояние |

Для готовой версии: если до сбоя шло воспроизведение, возобновить тот же выбранный ролик
с сохранённой позиции после восстановления соединения. Если были STOP/PAUSE/пустая очередь,
не начинать просмотр самостоятельно. Настройку автопродолжения добавить в M3;
в M0 проверить восстановление данных, без требования boot-автозапуска.

Сохранять состояние атомарно в локальном хранилище: предпочтительно Room/SQLite,
либо небольшой атомарный файл, если агент обоснует достаточность. Не хранить постоянные
подписанные stream URL — хранить videoId, получать поток перед воспроизведением.

Команды и события плеера обрабатывать последовательно. После STOP, NEXT или PLAY_NOW
запоздавший результат прежнего получения потока не должен запускать старое видео.
Достаточен простой идентификатор поколения запроса; отдельная сложная платформа не нужна.

## 7. Ссылки и плейлисты

Разрешить стандартные ссылки `youtube.com/watch?v=…`, `youtu.be/…`,
а также Shorts как отдельные завершённые видео, если extractor их поддерживает.
Проверять схему и настоящий hostname; `youtube.com.evil.example` не является YouTube.
Принимать только нормализованные идентификаторы, не произвольные media URL или локальные адреса.
Параметры трекинга удалять. В v0.1 просмотр начинается с начала; URL-параметр времени не применять скрытно.

Ссылка с `v` и `list` в режиме «Добавить видео» означает только указанный ролик.
Для всего плейлиста есть отдельное действие и предпросмотр.

M2: получить все доступные страницы публичного статического плейлиста, показать состав,
ошибки/недоступные элементы, количество и порядок; родитель выбирает элементы и нажимает
«Добавить выбранные». Частичный импорт нельзя выдавать за полный. Предлагаемый технический
лимит — 500 элементов за импорт; при достижении показать ограничение, не обрезать молча.

Сохраняется фиксированный список ID, а не «живое» подключение к плейлисту.
Новые ролики автора не добавляются без нового действия родителя.
Это не скачанная неизменяемая копия: доступность и содержимое на стороне YouTube могут изменяться.

MVP: публичные завершённые ролики и публичные статические плейлисты.
Прямые эфиры, незавершённые премьеры, бесконечные Mix/радио, приватные/возрастные/платные
видео, входящие в аккаунт подборки и обход ограничений доступа не поддерживаются.
Сообщать «не поддерживается» или фактическую причину, не пытаться обойти проверку доступа.

## 8. Потоки, качество и ошибки

Получать поток на самой приставке, рядом с моментом запуска. Сетевые операции — не на UI-потоке.
Сохранить необходимые заголовки, MIME и сведения о раздельных audio/video, возвращённые адаптером.
Media3 поддерживает разные контейнеры/протоколы, но работа зависит также от декодеров устройства [S2, S3].

Начальная цель качества — до 1080p SDR, без растягивания/обрезания кадра.
H.264/AAC — предпочтительный первый путь, если он доступен и воспроизводим на стенде;
другие кодеки не включать вслепую по названию процессора. Раздельные дорожки проверять со звуком.
Допустим честный fallback до 720p при проблемах, с указанием родителю; не обещать 1080p без проверки.

Ошибки разделять: неверная ссылка, недоступный ролик, неподдерживаемый тип,
нет интернета, ошибка extractor/ограничение сервиса, ошибка декодера.
При истечении/отказе media URL допустимо одно повторное получение для того же videoId;
не считать любой HTTP 403 автоматически только истечением ссылки.
При временном отсутствии сети — ограниченный backoff без частых запросов;
STOP/NEXT остаются действенными и отменяют отложенное продолжение.

Недоступный конкретный ролик можно пометить ошибочным и перейти только к следующему
явно выбранному. Если признаки системной ошибки затрагивают все видео, остановиться,
сохранить очередь и показать проблему родителю, а не вычеркнуть всю очередь подряд.
Никаких автоматических VPN, обхода CAPTCHA, импорта браузерных cookies или сторонних публичных прокси.

## 9. Доступ и удалённое управление

M1: первичная настройка на ТВ и создание родительского PIN. По дополнению владельца после HOME BETA
новый браузер входит только по действующему родительскому PIN, без одноразового кода и открытия
окна доступа на ТВ. Панель выдаёт отдельный случайный токен браузеру; доступ можно отозвать.
Существующие токены сохраняются. Ограничение неверных попыток — 5 за 10 минут для адреса клиента.
Пароли/PIN не хранить открытым текстом. Не использовать PIN как API-токен.
Нужны ограничение попыток, проверка входных данных и запрет управляющих запросов без доступа.

Не отдавать токены в URL/логи. Не разрешать CORS `*` для управления;
проверять Origin/Host и защищать изменение состояния от запросов посторонних сайтов.
Не загружать сторонние скрипты/аналитику в родительскую панель.

Для начального LAN-прототипа допустим HTTP только в доверенной домашней сети с явно
описанным ограничением: трафик не зашифрован. Не позиционировать его как защищённый от
перехвата посторонним участником сети. Доступ из интернета — только через защищённый канал.

M4: тот же пульт через SSH-туннель к доступному домашнему узлу либо подходящий частный VPN.
Если используется SSH-узел, он должен быть включён; ноутбук не становится обязательной
зависимостью для локального просмотра. Не разворачивать SSH-сервер внутри APK только ради этого.
Не открывать порты роутера, UPnP или административный API публично.
Если приставка недоступна, показать это; не обещать выполнение команды и не запускать её
неожиданно после возвращения сети. Облачная очередь команд в v0.1 отсутствует.

## 10. HOME и родительский режим (M3)

После подтверждения плеера добавить HOME и восстановление после boot.
Выбор HOME и ограничение выхода — отдельные механизмы. Lock Task/DPC проверяются отдельно
от screen pinning, из которого пользователь может выйти [S4].

Перед включением ограниченного режима на конкретной приставке сохранить сведения о штатном Launcher
и проверить доступный родительский выход. Если штатное provisioning требует сброса,
остановиться с описанием, не сбрасывать и не применять root автоматически.

Вход на ТВ: удержание заранее выбранной кнопки/комбинация → форма PIN.
Комбинация только показывает форму, а не даёт привилегии. Сам PIN не показывать в подсказке.
Родитель может выйти из просмотра, вернуть штатный Launcher и отключить ограничения.
Ошибки выхода не скрывать; не выключать единственный доступный способ восстановления.

Приёмка: Home/Back/Recents, медиа- и специальные кнопки, voice/search, CEC, клавиатура/мышь
при их использовании, системные диалоги и boot. Известные пути выхода перечислить.
Не заявлять абсолютную защиту от factory reset, root/ADB владельца или управления самим ТВ.
До успешного теста на H728 статус — «HOME/киоск не проверен», а не «защищено».

## 11. Не входит в первую версию

AI-модерация, автоматическое удаление интеграций, скачивание медиатеки, Google-аккаунт,
платные/закрытые ролики, приложение для ПК, облако, синхронизация нескольких приставок,
семейная аналитика, отдельный магазин контента, график занятий и лимиты экранного времени.
Не добавлять эти функции без отдельной задачи.

## 12. Приёмка и смысл «готово»

Проверки разделены по этапам в `ACCEPTANCE.md`.
M0 принят только как техническая основа плеера; M1 — как локальное управление;
M2 — как импорт; M3 — как проверенный родительский режим на конкретной H728;
M4 — как удалённое управление в реальной сети.

Каждый отчёт содержит версии, команды, commit и реальные результаты.
Недоступное оборудование означает NOT_RUN, а не PASS.
Риски нестабильности YouTube и изменение контента у источника не исчезают после успешного теста.
