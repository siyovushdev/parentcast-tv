# M1 — родительский LAN-веб-пульт

## 1. Реализация и границы

Ветка `m1/lan-parent-control`, база `m0/ytdlp-media3` (`6c5581e66514d820a2fa6e261cb649d2ed1806bc`).
Implementation commit: `e396967fc774f67287f6d1d4fbaf62a495fc2ab1`.
Cleanup commit: `ff2e4b18443d5e015351e36858c9bc12aee71cc7`.
Draft PR: https://github.com/siyovushdev/parentcast-tv/pull/4.

Реализовано в существующем Android-модуле:

- NanoHTTPD 2.3.1, порт 8765, локальные HTML/CSS/JavaScript без frontend framework и внешних ресурсов.
- Русская адаптивная панель: одна/несколько ссылок, очередь и текущий ролик, play/pause/next/stop,
  play-now, move/delete/clear pending, устройства и реальные ошибки плеера.
- PIN на ТВ с PBKDF2-HmacSHA256 (120000 итераций), смена PIN без очистки данных, одноразовый код
  на 2 минуты, отдельные токены устройств и отзыв. Хранятся только хеш PIN и SHA-256 токенов.
- Bearer-авторизация, ограничение попыток PIN, Host/Origin/Referer/custom-header проверки,
  отсутствие CORS, защита от CSRF/DNS rebinding, security headers и CSP.
- Последовательные команды на main thread, атомарные JSON-файлы, идемпотентность с TTL 24 часа
  и лимитом 100 ответов, версии очереди и HTTP 409 при конфликте.
- Исключение PIN, токенов, idempotency-ответов и YouTube cookies из backup/device transfer.
- Сохранены PlaybackCoordinator, очередь, yt-dlp + Media3, AtomicQueueStore и debug UI.
  Добавлен автоматический показ PlayerView при удалённом запуске и корректный статус после resume.

Исправленные при приёмке дефекты IN SCOPE/REGRESSION: чтение JSON через `parseBody`, синтаксис
обработчика отзыва в JavaScript, повтор команды с новым ключом, гонка одинаковых запросов,
время состояния при простом чтении, пустой PIN, отсоединённый PlayerView, отсутствие повторного
first-frame callback после resume и неизвестный NanoHTTPD статус 421.

M2–M4, HOME, Device Owner, Lock Task, Launcher, Happ, FamilyTV и системные настройки не изменялись.
Merge и Release не выполнялись.

## 3. Аппаратная приёмка H728 и браузеров

arm64-v8a, 1920×1080. В `adb devices -l` доступна только H728; Android-телефон отсутствует.

## 4. Ограничения и оставшиеся проблемы

Полная аппаратная приёмка M1 не объявляется: Android-браузер и физическое выключение Ubuntu остаются
NOT_RUN. Остальные проверенные пункты M1-02…M1-07 — PASS; нерешённых FAIL в реализованном объёме нет.

HTTP не шифруется и предназначен только для доверенной LAN. HTTPS, удалённый доступ и production-
авторизация YouTube не реализованы. Тестовые cookies оставлены на H728 по требованию владельца,
не читались и не удалялись. Субъективный звук и обрыв сети M0 остаются NOT_RUN и не переоценивались.
На устройстве оставлена тестовая очередь в STOP; тестовые токены отозваны. Это не защищённый детский режим.
