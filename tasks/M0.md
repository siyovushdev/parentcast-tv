# M0 — рабочая основа плеера

## Результат

Реальный Android-проект, а не только исследования и отчёт.
Debug APK: собственный fullscreen-плеер, получение выбранного YouTube-видео через extractor,
минимальная очередь и отдельный отладочный родительский экран ввода ссылок/управления.
Код пригоден для продолжения в M1, но это ещё не защищённый детский режим.

## 1. Окружение и репозиторий

Прочитать AGENTS и ТЗ. Работать в отдельном каталоге `parentcast-tv`.
Проверить текущий каталог, Git status/remote, доступные JDK/Android SDK/ADB и `gh auth status`.
Не печатать секреты. Проверить, что GitHub-аккаунт — `siyovushdev`.
Проверить наличие `siyovushdev/parentcast-tv`: 403/сетевую ошибку не трактовать как отсутствие.

Если repo не существует и GitHub CLI авторизован, создать **private** репозиторий.
Сначала сохранить предоставленные документы и `.gitignore` в локальный Git с веткой `main`.
Пример команды для действительно нового repo после первого commit:

```bash
gh repo create siyovushdev/parentcast-tv --private --source=. --remote=origin --push
```

Подтвердить remote, видимость PRIVATE и наличие первоначального commit.
Если уже есть repo с таким именем, не создавать второй и не затирать:
сначала проверить, что это тот же новый проект. При конфликте продолжить только безопасную
локальную подготовку и сообщить о конфликте.
Если GitHub недоступен, локальную реализацию не бросать: отметить публикацию BLOCKED,
не выдумывать URL репозитория/PR.

Начать ветку `m0/player-spike`. Реализацию не писать прямо в main.

## 2. Минимальный Android-каркас

Kotlin, один app-модуль, Gradle Wrapper, точные версии библиотек.
Android package `dev.siyovush.parentcast.tv`, debug suffix `.debug`.
Режим landscape. Launcher/Leanback entry, работа без touchscreen.
В M0 не объявлять и не назначать HOME, не внедрять DPC, Lock Task или boot-автозапуск.

Не обновлять всю систему ради проекта. Если зависимости несовместимы с установленным
SDK/JDK, выяснить минимальное изменение и отразить ограничение, не скрывать его.

## 3. Получение и воспроизведение

Сначала проверить актуальное API и доступную воспроизводимую версию NewPipe Extractor
по первичному upstream. Не выдумывать методы, не строить собственный extractor.
Выделить небольшой `YouTubeSource`: распознать ссылку, получить метаданные и воспроизводимые
audio/video источники с необходимыми заголовками. Работать не на main thread.
Рекомендации extractor не использовать для очереди и не показывать ребёнку.

Media3/ExoPlayer с отключённым контроллером в экранном режиме просмотра.
Никаких WebView, iframe, запуска YouTube/VLC или внешнего браузера.
Поддержать один выбранный ролик, затем последовательность минимум из трёх.
Раздельные дорожки обрабатывать корректно; видимое видео без звука не считать успехом.
Качество и фактический кодек записать в диагностику для родителя.

Настроить отмену и защиту от устаревших ответов: STOP/NEXT/PLAY_NOW нельзя отменить
поздним результатом extractor. Ошибки сети не превращать в бесконечные быстрые повторы.
Не получать Google-cookies или данные чужих аккаунтов. Подписка Premium в M0 не используется.

## 4. Очередь и хранение

Минимальные команды отладочного экрана: добавить, играть, пауза/продолжить, следующий,
стоп, удалить ожидающий элемент. UI выбора доступен только как отдельно обозначенный
debug-инструмент, не появляется поверх просмотра.
В начале очередь пуста; не поставлять «полезные» ролики от имени родителя.
Отладочные тестовые ссылки хранить отдельно от одобренного детского контента.

Окончание последнего ролика → наш экран ожидания. Недоступный ролик → понятная ошибка;
нет внешнего fallback. Сохранить videoId, queueItemId, порядок, позицию, play/pause/stop intent.
Перезапуск процесса не должен терять очередь. Не сохранять stream URL вместо videoId.
Никаких плейлистов, HTTP-сервера и веб-пульта в M0.

## 5. Проверка

Unit-тесты для парсинга ссылок и опасных hostname, очереди, сохранения/восстановления,
недоступного ролика, позднего ответа extractor после STOP/NEXT.
Собрать debug APK и запустить lint доступной конфигурации.
Зафиксировать точные команды, версии, количество выполненных тестов и результат.
Не выдавать сетевую заглушку за живое видео.

Аппаратная проверка только на однозначно определённой H728 через уже доступный ADB.
Не делать network scan и не использовать старый IP как единственное доказательство.
Разрешена установка нового debug APK без удаления других приложений и смены Launcher.
Если ADB недоступен или устройство неоднозначно, завершить код/сборку, дать APK и инструкцию,
аппаратные пункты отметить NOT_RUN. Не устанавливать на случайный подключённый телефон.

Пройти применимые пункты `docs/ACCEPTANCE.md` для M0. Три реальные VOD, звук,
переходы, конец очереди, ошибка, потеря сети, сохранение данных; минимум 20 минут просмотра.
Не утверждать поддержку всех роликов по одному удачному тесту.

## 6. Передача результата

Добавить `docs/reports/M0.md`: окружение, зависимости, реализация, таблица проверок,
фактические ограничения, способ повторения проверки и пути артефактов.
Логи очищены от tokens/cookies/подписанных URL. Сохранить уведомления лицензий зависимостей.

Commit/push в `m0/player-spike`, открыть **Draft PR** к main при наличии GitHub-доступа.
Никаких merge, GitHub Release, публичной публикации APK и перехода к M1 без следующего задания.
Отчёт владельцу — пять пунктов по AGENTS.md, с APK и его SHA-256.

## Условия остановки

Если текущий upstream extractor не даёт воспроизводимый поток, не подменять решение
iframe или внешним YouTube. После двух целевых попыток исправления представить
логи/ошибку/проверенные версии и минимальный вариант следующего шага.
Не переписывать весь стек и не подключать платную инфраструктуру без нового решения владельца.
