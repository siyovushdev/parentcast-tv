Минимальные варианты зафиксированы: (A) использовать существующий общий ledger
записей, завершать timestamp после scan, периодический пересчёт5s и принудительный

фрагмента, API читает тот же ledger; (B) оставить полную подготовку до просмотра;
(C) новый RAM/внутренний cache-tier — смена архитектуры, не выполняется.
Выбран A в существующей архитектуре. Все production media writers уже разделяют
один MediaBudget; записи инкрементируют ledger под общим lock, удаления временно
дают только консервативный завышенный учёт. Живой mounted/writable/free-reserve
проверяется каждой физической записью. Ошибка любой записи инвалидирует ledger.
Это последняя ограниченная итерация; если реальный просмотр всё ещё не проходит,
зафиксировать FAIL/оставшуюся причину и минимальные варианты, не расширять проект.
