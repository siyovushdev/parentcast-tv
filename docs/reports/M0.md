# Отчёт M0 — основа плеера

## 1. Результат и границы

Ветка `m0/player-spike`, проверенный implementation commit:
`66488dc943727c94858b085fb93880fcd68320cd`.

Реализован один Android app-модуль с package `dev.siyovush.parentcast.tv` и debug applicationId
`dev.siyovush.parentcast.tv.debug`. Есть нативный fullscreen-плеер Media3, NewPipe Extractor,
минимальная очередь, атомарное сохранение и отдельный debug-экран ссылок/команд. Начальная
очередь пуста; тестовые ролики не добавляются от имени родителя.

Это не защищённый детский режим. HOME, Device Owner, DPC, Lock Task, boot-автозапуск, HTTP-сервер,
веб-пульт, плейлисты, Google-логин/cookies и внешние плееры не добавлялись. M1–M4 не выполнялись.

## 3. Реализация

- `YouTubeVideoIdParser`: только HTTPS и точные hostname YouTube; watch, youtu.be и Shorts.
  Принимается ровно один нормализованный 11-символьный videoId. Параметры list/time/tracking не
  превращаются в импорт плейлиста или скрытый старт с позиции.
- `NewPipeYouTubeSource`: сетевой extractor через OkHttp без cookie jar, вне UI-потока. Выбираются
  только progressive HTTPS MP4 H.264 до 1080p и AAC/M4A. Для video-only и audio создаются отдельные
  `StreamSpec`; Media3 объединяет их через `MergingMediaSource`. Другие кодеки вслепую не включаются.
- `PlaybackCoordinator`: add/play/pause-resume/next/stop/delete-pending; добавление не прерывает
  текущий ролик. Уникальный queueItemId допускает повтор одного videoId. Generation guard и отмена
  coroutine не дают запоздалому ответу запустить прежний ролик после STOP/NEXT. Для HTTP 403 —
  не более одного повторного получения того же videoId; быстрого сетевого retry-loop нет.
- `AtomicQueueStore`: JSON в том же каталоге, временный файл, `fsync`, `ATOMIC_MOVE`. Сохраняются
  только ID, порядок, позиция, PLAY/PAUSE/STOP и признак конца; подписанные media URL не сохраняются.
  Позиция пишется периодически и при pause/stop. Восстановление происходит при новом запуске Activity,
  без boot-автозапуска.
- `MainActivity`: landscape, Launcher и Leanback entry, touchscreen не требуется. У PlayerView
  отключён контроллер, видео сохраняет пропорции. Debug-экран открывается отдельно через Menu/Settings
  или удержание DPAD Center и явно обозначен как незащищённый прототип.
- Диагностика родителя содержит выбранное и фактическое разрешение/кодеки по событиям Media3,
  без media URL. Тексты GPL-3.0 и Apache-2.0 упакованы в `assets/licenses/`; см.
  `docs/THIRD_PARTY_NOTICES.md`.

## 5. Приёмка M0 и H728

Целевое устройство однозначно подтверждено по совокупности evidence: владелец указал текущее ADB-
подключение, оно единственное, `ro.soc.model=h728`, `ro.soc.manufacturer=Allwinner`, Android 14
(API 34), 1920×1080. Product/model `ADT-3` не совпадает с названием SoC, но не опровергает H728.

Первый APK commit `8c02b31` выявил IN SCOPE дефект запуска: NPE при обращении к
`window.insetsController` до создания DecorView. Настройка system bars перенесена после
`setContentView`; commit `5e82791` успешно запущен на устройстве. HOME не менялся.

|---|---|---|
| M0-01 | PASS | Чистый checkout commit `66488dc`, 49 задач, BUILD SUCCESSFUL, APK |
| M0-02 | PASS | 9 JVM-тестов; на H728 `youtu.be.evil.example` отклонён, очередь не изменилась |
| M0-03 | FAIL | VOD запущен, но YouTube вернул `LOGIN_REQUIRED` для anonymous watch; видео/звук нет |
| M0-04 | NOT_RUN | Раздельные дорожки и синхронный звук не проверены без воспроизведения |

Локальные очищенные evidence вне Git: `artifacts/m0/h728-player-empty.png`,
`h728-stop-after-60s.png`, `h728-restart-stop.png`, `h728-invalid-host.png`,
`h728-vpn-detailed-error.png`, `h728-service-block-stopped.png`, `h728-service-block-restart.png` и
`h728-vpn-logcat-sanitized.txt`. JSON содержит прежние три `queueItemId`/`videoId`, `currentIndex=0`,
`positionMs=0`, `intent=STOP`. После force-stop/restart запрос не повторяется.

Сетевая история: сначала `www.youtube.com` не резолвился. После включения Happ владельцем DNS
восстановился, HTTPS `https://www.youtube.com` вернул 200 OK. ICMP больше не использовался как
критерий, поскольку владелец настроил проверку доступности по TCP. Затем NewPipe получил точный
`SignInConfirmNotBotException`: YouTube временно запретил anonymous watch с текущего выходного IP
(`LOGIN_REQUIRED`, «Sign in to confirm that you're not a bot»). Cookies, Google-login, CAPTCHA-bypass
и сторонние прокси не добавлялись. Для этой системной ошибки код теперь сохраняет STOP и очередь,
не повторяя запрос автоматически после restart.

Минимальный 20-минутный сеанс воспроизведения: **NOT_RUN**. Три VOD, звук и синхронность:
**NOT_RUN**. Собранный и запущенный APK не является доказательством доступа к видеопотокам YouTube.

На debug-экране использовать три выбранных родителем публичных VOD, проверить звук, фактические
кодеки, порядок и естественный конец хотя бы одного короткого ролика. Затем отдельно проверить конец
очереди, STOP/NEXT во время загрузки, недоступный ролик, отключение/возврат сети и перезапуск процесса
во всех PLAY/PAUSE/STOP. Суммарный сеанс — не менее 20 минут. Не менять HOME или системные настройки.

## 7. Ограничения и один следующий шаг

Фактическая совместимость extractor, доступность роликов, качество 1080p, звук и декодеры H728 не
подтверждены: текущий выходной IP Happ получает `LOGIN_REQUIRED` для anonymous watch. H.264/AAC —
единственный выбранный путь M0; другие кодеки получат управляемую ошибку. YouTube может ограничивать
anonymous доступ; Premium и авторизация не используются. До полной аппаратной приёмки M0 остаётся
техническим прототипом, а не готовым детским устройством.

Следующий шаг: владельцу выбрать другой выходной сервер Happ, после чего повторить M0-03…M0-07 и
M0-09…M0-11 с очищенными свидетельствами и 20-минутным сеансом. Переход к M1 этим отчётом не
разрешается.
